# M3 雷达与 LIO 实施计划

> 执行方式同 M0–M2（内联 TDD，小步提交，CI 验证）。设计依据：设计文档 5.2 节。

**目标：** Mid-360S（或仿真）→ 自身点过滤 → FAST_LIO → `g1d_lio_bridge` 输出 `odom → base_link`（50 Hz，LIO + 轮速外推）、`/odometry`、`/g1d/lio_health`，障碍点云 `/g1d/obstacle_cloud` 供守护与代价地图使用；CI 闭环验证 LIO 精度与自身点过滤。

## 上游阅读结论（2026-11-17）

| 上游 | 版本 | 结论 |
|---|---|---|
| livox_ros_driver2 | `2144554` | 已官方支持 Mid-360s 与 Jazzy。无 PTP 时每包时间戳 = 主机 `high_resolution_clock::now()`（= system_clock），有 PTP 时为 PTP 时间（主时钟即主机）→ **不需要时钟映射补丁**（设计文档 4.2 节相应修订）。只需补 colcon 用的 `package.xml` 与 CMake 默认值；配置 JSON 由 `g1d_bringup` 生成 |
| Livox-SDK2 | `c0796f0`（v1.3.1 之后，含 Mid-360s / 24.04 修复） | 未修改，子模块放 `third_party/Livox-SDK2`（不在 `src/`，避免被 colcon 当作 cmake 包），`scripts/install_livox_sdk2.sh` 编译安装到 `/usr/local` |
| FAST_LIO（ROS2 分支） | `cc3c9e8` + ikd-Tree | 补丁：C++17；`common.world_frame` / `common.body_frame` 参数（原写死 `camera_init` / `body`）；`publish.tf_en`（关闭自带 TF）。`body` = IMU 系；`/cloud_registered_body` = 去畸变当帧点云（IMU 系） |

## 任务

1. **Livox**：子模块 `third_party/Livox-SDK2`；安装脚本；vendor `livox_ros_driver2`（原样 → 补丁）。
2. **FAST_LIO**：vendor（含 ikd-Tree 源码，原样 → 补丁）。
3. **`g1d_lidar`（C++）**：`self_filter`（CustomMsg → CustomMsg，盒子在任意 TF 坐标系，每帧查 TF）、`utlidar_adapter`（PointCloud2 + 可选逐点时间字段 → CustomMsg）；gtest 测盒子过滤与时间换算。
4. **`g1d_core.lio`**：SE(3) 工具、`LioAnchor`（首帧锚定 `T_odom_lio`）、`planar()`（投影到 SE(2)）、`WheelExtrapolator`（轮速增量外推）、`LioHealth`（超时、跳变、z 漂移、轮速一致性）；pytest。
5. **`g1d_localization`**：`lio_bridge` 节点（订阅 FAST_LIO `/Odometry` + `/chassis/odom` + TF `base_link → livox_imu`，发布 TF `odom → base_link` 50 Hz、`/odometry`、`/g1d/lio_health`）。
6. **`g1d_lidar_sim`（C++）**：跟随 `/sim/ground_truth` 生成 Mid-360 非重复扫描 CustomMsg（逐点时间、运动畸变、倒装外参来自 TF）+ IMU 200 Hz（g 单位、偏置噪声）；可选机身自遮挡盒子；世界文件与 `g1d_sim` 共用（加地面 / 天花板）。
7. **`g1d_bringup`**：`lio.launch.py`（`lidar_source:=livox|unitree|sim`）、`config/fast_lio.yaml`、`config/self_filter.yaml`、Livox JSON 模板；`sim.launch.py` 增加 `lio:=true`。
8. **CI 闭环**：`room` 世界，按路线驾驶约 10 m 闭合轨迹，`/odometry` 与真值对比（终点误差 < 0.10 m / 2°）；静止时 `/g1d/obstacle_cloud` 在机身盒内无点。
